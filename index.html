AI Agents 的迴圈與圖
從五篇論文看 Agent 的循環架構與節點分工

知識庫：個人 LLM Wiki（由 Google Colab 筆記本 ingest 5 篇 arXiv 論文建立）

主題：ReAct ・ Reflexion ・ Toolformer ・ Generative Agents ・ CRAG

海洋大學 生成式AI：文字與圖像生成的原理與實務以 ← → 或空白鍵翻頁

為什麼談「迴圈」與「圖」？

  • 單次生成＝一條直線：prompt → answer，錯了也照樣交出去。
  • Agent＝把生成放進回饋迴圈：行動後觀察結果，決定下一步。
  • 迴圈裡每個位置（思考、工具、記憶、檢查）都可換零件——擺成節點與連線，就是 graph。
思考
→
行動
→
觀察
↺ 觀察結果回填，再進下一輪思考

這是所有 Agent 框架的最小骨架；五篇論文各補一塊零件。

零件一：ReAct — 把「想」與「做」交錯

循環本體Thought → Action → Observation

模型先產出思考文字，再選擇行動（例如查資料），把行動結果當觀察讀回來，進入下一輪。推理接地氣，不再憑空編造。

沒有 ReAct 的迴圈，後面的反思與校驗都無處可掛。

Thought（我缺什麼資訊）
↓
Action（搜/search:…）
↓
Observation（讀回結果）
↺ 未達目標則回 Thought
arXiv:2210.036293 / 8

零件二、三：Reflexion 反思節點 ＋ Toolformer 工具節點

Reflexion失敗後寫「自我回饋」再重試

迴圈跑完仍失敗時，模型用文字寫下失敗原因，存入情節記憶，下一次迭代把這段回饋當上下文——不用重訓參數，靠語言自我修正（模型內 loop）。

Toolformer行動節點的可執行清單

模型自 supervision 學會何時插入 API 呼叫（搜尋、計算、翻譯），把「行動」從純文字升級成真能執行的工具調用——擴展 Agent 可做的事。

一個讓迴圈「會改進」，一個讓行動「會伸手」。

arXiv:2303.11366 ・ arXiv:2302.047614 / 8

零件四、五：Generative Agents 記憶 ＋ CRAG 校驗

Generative Agents觀察沉澱 → 反思 → 索引取回

把每日觀察寫進記憶流，定期把零散觀察合成高階反思，再依相關性取回——迴圈有了跨時間的狀態，行為才连貫可信。

CRAG檢查節點前移：先驗收再進迴圈

對檢索文件做品質分級（正確／含糊／錯誤），含糊或錯誤即觸發重新檢索與整理——髒資料不進後續節點，把校驗從末端移到入口。

記憶讓迴圈「記得住」，校驗讓迴圈「吃得乾淨」。

arXiv:2304.03442 ・ arXiv:2401.158845 / 8

質疑反問：拼成完整 graph 之後呢？

  • Q1 五個零件全開，迴圈會不會永遠不結束？
  • 迭代上限、成本與收斂條件要誰來定？反思與重試各設幾次？
  • Q2 CRAG 的分級器自己錯了怎麼辦？
  • 把關者也是模型——校驗節點的置信度如何校準，誰校驗校驗者？
  • Q3 Reflexion 的文字回饋會不會固化成偏見？
  • 錯誤的自我解釋存入記憶後，會不會在後續任務反覆污染判斷？
  • Q4 記憶取回的「相關性」等於「正確性」嗎？
  • Generative Agents 按相似度召回，過時觀察混進上下文如何偵測？

總結：一套骨架，五塊拼圖

  • ReAct 給骨架：思考—行動—觀察的迭代循環是 Agent 的最小單元。
  • Reflexion／Toolformer 補節點：一個管失敗改進，一個管行動能力。
  • Generative Agents 加狀態：記憶流讓迴圈跨時間運作。
  • CRAG 設門檻：入口校驗決定整個 graph 的資料品質。
  • 設計自己的 Agent 系統時，先畫迴圈、再選節點、最後決定把關位置。
